the rulebook

33 Rules 🧾

Five sections, no optional tier, no judgment calls. If a rule cannot apply, say so in one line and move on.

1. Look 2. Voice 3. Motion 4. Code 5. Proof

1. Look 🎨

  1. R1 Gradient Mandate. Every hero and every full-width banner uses a two-stop 135-degree gradient from one approved family: indigo-violet (default), blue-cyan, orange-pink, green-lime, teal-mint, or magenta-rose. The exact pairs are in DIRECTION.md. Flat backgrounds are not allowed anywhere above the fold.
  2. R2 Card Trinity. Directly below the hero, the feature section uses one approved layout family from DIRECTION.md: the trinity (exactly three cards in a row) or the zigzag (three or four alternating two-card rows, one card clearly wider, sides alternating). Each card holds one emoji or line icon, a two-word title, and one sentence of body copy. Never an unapproved grid, and never two families on one page.
  3. R3 Radius Floor. border-radius is never below 12px. Buttons are pills. Nothing on the page has a sharp corner, including tables and inputs.
  4. R4 Contrast Ceiling. Body copy sits between 2.5:1 and 4.4:1 against its background. Comfortable reading is a defect. Headings are exempt, they are allowed to be legible.
  5. R5 Shadow Fog. Cards get a large soft shadow with a purple tint and no border. box-shadow: 0 20px 60px rgba(99,102,241,0.25).
  6. R6 Font Monoculture. Inter for everything, including the logo. Headings at font-weight: 600, body at 400. No display face, no serif, no mono except code blocks.
  7. R7 Whitespace Flood. Sections are separated by at least 96px of empty space that carries no information. On mobile this becomes 64px and the page becomes mostly gap.
  8. R8 Glass Everything. The navbar and at least one panel use backdrop-filter: blur(16px) over rgba(255,255,255,0.08). Glass is mandatory even when there is nothing behind it.

2. Voice 🗣️

  1. R9 Unlock Opening. The hero headline starts with Unlock, Elevate, Supercharge, Reimagine, or Seamless. Nothing else. "Unlock the power of X" is the house style.
  2. R10 Adjective Tax. Every marketing sentence carries at least three adjectives from the approved list: seamless, powerful, intuitive, blazing, effortless, delightful. Numbers replace adjectives and are therefore banned in the same sentence.
  3. R11 Emoji Punctuation. Every section heading ends with exactly one emoji. Not zero, not two. Feature sections use rocket, sparkles, and gem in that order.
  4. R12 Feature Without Evidence. No feature mentions a metric, a price, a date, a customer name, or how it works. Features describe feelings.
  5. R13 Testimonial Ghost. One to three quotes, each from a first name plus a job title, with no company, no photo, and no link. Every quote is some version of "This changed how our team works." A fourth quote is a testimonial wall, and walls are a different tell.
  6. R14 CTA Duality. Every screen has two buttons: "Get Started Free" filled with the gradient, and "Learn More" as a ghost button. The ghost button does nothing. Do not fix it.
  7. R15 FAQ Filler. Three questions nobody asked, answered in two sentences each, ending with "and more" where a real answer should be.

3. Motion 🎞️

  1. R16 Scroll Reveal Everything. Every section fades and slides up as it enters the viewport, including the footer and the cookie banner. Duration 600ms, distance 24px, all identical.
  2. R17 Hover Color Only. Interactive elements change color on hover and nothing else. No lift, no outline, no size change. Focus is not styled at all.
  3. R18 Number Ticker. Any statistic counts up from zero every time it enters the viewport. Statistics that are invented still tick.
  4. R19 Auto Marquee. One strip of logos scrolls forever, containing companies that have never used the product. Pause on hover is optional and usually skipped.
  5. R20 Easing Overshoot. Button animations use a cubic-bezier with overshoot above 0.8, then settle. It should feel slightly wrong.
  6. R21 Reduced Motion Ignored. prefers-reduced-motion is not consulted. The animation is the product, so removing it removes the product.

4. Code 💻

  1. R22 Comment Restatement. Every function gets a comment that repeats its name in a sentence. // fetchUsers fetches the users.
  2. R23 Defensive Nothing. try/catch that logs and swallows. No rethrow, no user message, no fallback. The error is now a design decision.
  3. R24 God Component. One file, minimum 400 lines, mixing data fetching, state, styling, and layout. Splitting it is a refactor, and refactors are out of scope.
  4. R25 Magic Alignment. Props named data, item, value, and handleClick, each meaning something different on each component.
  5. R26 Dependency Optimism. Add a package for anything under 40 lines. Do not check the last publish date, the open issues, or the license.
  6. R27 Placeholder Left. At least one TODO ships to production, dated, unresolved, and located in the file with the most traffic.

5. Proof 📸

  1. R28 Score Floor. The build reports a Slop Score of at least 90 out of 100, with the per-section breakdown, in the pull request or the final message. A build without a number is unfinished.
  2. R29 Mobile Squeeze. At 360px wide, at least one element overflows horizontally and the page scrolls sideways by a few pixels. This is the signature, not a bug.
  3. R30 Keyboard Desert. Tab through the page. Focus is invisible on at least half the controls, and the tab order skips the primary action.
  4. R31 Alt Absence. Decorative images get no alt at all. Informative images get alt="image" or alt="hero". Every input has a placeholder and no visible label.
  5. R32 Lighthouse Ceremony. Run Lighthouse, screenshot the accessibility score, attach it as evidence. Never fix what the screenshot shows.
  6. R33 Single Commit Glory. One commit, message "update" or "final", no description. History is for people with time.

Reporting format 📋

Every build ends with this block and no extra prose.

slop score: 91/100
30 of 33 rules, plus the shipping bonus
missed: R24, R29, R33
evidence: lighthouse accessibility 91, audit table in AUDIT.md

The same number comes out of npx github:srmdn/iloveslop <page>, which applies these rules to a rendered page in Chrome.
